# イベント契約とファネル

[English](../event-contracts.md)

## イベントを選ぶ

導入先は収集プロファイルにイベント名と許可する項目を宣言します。発火はアプリケーションが担当します。期限、順序、帰属を含むファネルの定義は分析パイプラインが担います。同じイベント記録を複数のファネル定義で使用できます。

| イベント | 収集のタイミング |
| --- | --- |
| 検索クエリ | ユーザーが検索を確定したとき。検索を再試行するときはクエリ ID を保持し、新たに検索するときは別の ID を割り当てます。 |
| 結果表示 | アプリケーションが結果セットを描画したとき。結果がゼロ件の場合も含みます。 |
| 結果の露出 | 登録したカードが、前面のタブで設定された表示面積に達したとき。結果セットと表示位置の組で重複を排除します。 |
| 結果のクリック | ユーザーが表示された結果を操作したとき。クエリ ID、結果 ID、観測した順位を渡します。 |
| 詳細表示 | 詳細ページまたはルートを描画したとき。 |
| カート追加・求人保存 | アプリケーション内で処理が成功したとき。 |
| 購入・応募 | サービスが業務上の完了を確定したとき。確定の記録にはサーバー側のイベントを優先します。 |

EC のファネル例は検索 → 結果 → 詳細 → カート追加 → 購入です。求人では検索 → 結果 → 詳細 → 保存 → 応募を使えます。セッション ID は訪問内の活動をまとめます。画面をまたいだ帰属のために明示的な検索の文脈を保持し、コンバージョンの集計期間はセッションの有効期限と独立に決めます。

## カードの露出

ブラウザの計測ヘルパーは、ホストが登録したカードとビューポートの幾何学的な交差を計測します。前面のタブでカードの面積が 50% 以上表示されると、デモはクエリ ID、表示結果セット ID、1 始まりの順位付きで `result_impression` を記録します。登録した結果セットごとに、同じ順位の発火は一度です。結果セットを差し替えたり並べ替えたりした場合は、新しい監視インスタンスを使います。再利用する要素は登録を解除し、画面遷移や同意撤回時には監視を終了します。

収集プロファイルの `impressions.minVisiblePercent` は 1〜100 の整数を取り、TOML、YAML、JSON で指定できます。既定値は [Google Tag Manager の要素の表示トリガー](https://support.google.com/tagmanager/answer/7679410?hl=ja) に合わせています。表示の最低継続時間は設けておらず、重なった要素による遮蔽や利用者の注視は計測しません。[Intersection Observer の仕様](https://www.w3.org/TR/intersection-observer/)。

GA4 に倣ったセッションは `session.inactivityMinutes` で独立して変更できます。設定範囲は 1〜1440 分の整数で、既定値は 30 分です。[GA4 のセッション](https://support.google.com/analytics/answer/9191807?hl=ja)。

## イベント固有の項目を宣言する

```toml
[events.job_saved.fields.job_id]
type = "string"
required = true
maxLength = 100
```

保存に成功したら、アプリケーションは `trackEvent("job_saved", { metadata: { job_id } })` を呼びます。イベント固有の項目は `metadata` に入れます。位置を計測したイベントは、`event_attributes` と、そのパスに宣言した UBI 拡張を含められます。現段階のコレクターは 1 始まりの順位を受け付けます。起点となる検索がわかる場合は `query_id` を指定します。

遅着した応答、レート制限や再試行、再描画、仮想化された一覧、タブをまたぐ挙動を各導入箇所でテストします。配送を識別する ID と、注文 ID などの業務 ID は、それぞれ異なる重複排除に使います。

## 滞在時間と検索指標の設計案

以下は M2 で導入先が選択して有効にする計測の設計案です。現在のコレクターはイベント時刻とセッション ID を記録します。

| 指標 | 観測と集計の単位 |
| --- | --- |
| セッション経過時間 | 割り当てられたセッションの開始からイベントまで。新規セッションではゼロから始まる。ファネル分析用の実経過時間で、無操作の時間も含みうる。 |
| 詳細ページの活動時間 | 描画された詳細画面ごとに対象区間を合算する。同意後、画面が表示されフォーカスを得た時点で開始。フォーカス喪失、非表示、画面離脱、同意撤回、設定した無操作期限のうち最初の時点で区間を閉じる。 |
| 検索結果の滞在時間 | 計測できる遷移先での活動時間を、起点となる結果クリックに帰属させる。クリックから一覧に戻るまでの実経過時間は別指標にする。遷移先を観測できない場合や戻りを観測できなかった場合は、該当指標を不明として扱う。 |
| 初回クリックまでの時間 | 特定の結果セットを描画してから最初にクリックするまで。未クリックの表示件数と観測期間も別に示す。 |
| 検索の成否 | 描画した一覧に対するゼロ件率、表示順位別の露出あたり CTR、検索の一連の流れにおける再検索、定義した帰属期間内のコンバージョンを測る。分母と観測できた割合も記録する。 |

同じ文書内の区間には単調時計を使います。タイマーが数時間遅れても、最後の対象操作に無操作期限を足した時点で加算を打ち切ります。この方法は離席中の過大計上を抑える一方、操作せずに読む時間を短く見積もる場合があります。操作再開、画面遷移、戻る・進むキャッシュからの復元では新しい区間を開始します。タブをまたぐページ表示、クリック、結果セットの ID を区別し、利用者単位の時間を求める際は重複区間の単純合算を避けます。

経過時間は集計に必要な粒度に丸め、対象イベントなどの記録機会に増分を付けます。時間を記録するための通知はセッションの有効期限を延ばしません。同意撤回時は未送信の区間を破棄します。入力内容、押したキー、ポインターの軌跡は収集項目に含めません。計測を有効にする前に、端末の休止、非表示タブ、3時間の離席、セッション期限、離脱の欠測、再送を検証します。[GA4 のエンゲージメント](https://support.google.com/analytics/answer/11109416?hl=ja) · [クライアントとサーバーの滞在時間計測の研究](https://www.microsoft.com/en-us/research/publication/comparing-client-server-dwell-time-estimates-click-level-satisfaction-prediction/) · [Page Lifecycle API](https://developer.chrome.com/docs/web-platform/page-lifecycle-api)
