## 収集とイベント契約

TypeScript のホストがアプリケーションからの呼び出し、ブラウザの時計、Web Crypto、IndexedDB、配送を扱います。セッションの期限判定は Rust/WASM が担います。導入先はプロファイルの宣言と TypeScript の収集 API を使ってイベントを追加します。アプリケーションは JSON、YAML、TOML でイベント名と項目を宣言し、各サービスの処理に応じたタイミングで `trackQuery` と `trackEvent` を呼びます。コンパイラは等価な正規化済み JSON と、ブラウザと受信側で共有する SHA-256 のプロファイル識別子を生成します。検索語の収集はサイトで明示的に有効化します。

ホストは、表示した結果に対応するクエリ ID、結果 ID、画面に表示した 1 始まりの順位を渡します。検索 API がすでに Query レコードを記録している場合、その ID をブラウザ側のクリックに使用できます。イベント固有の独自項目はエンベロープのメタデータで検証します。対応する UBI 拡張パスはプロファイルに照らして検証し、UBI ペイロードに格納します。`event_attributes` を渡す場合は位置が必要です。

## UBI とセッション

受信側では、収集契約と選択された [UBI v1.3.0 スキーマ](../../schema/upstream/ubi-1.3.0/README.md) を検証します。既定は厳密検証です。互換モードは既知のアクション名とオブジェクト種別に生じるスキーマの分岐の重複に対応します。サンプルでは互換モードで `product` に対する `click` を送信します。

セッションの既定値は無操作から 30 分です。同一オリジンのタブ間では、活動ごとに一つの IndexedDB トランザクションを使ってセッション状態を共有できます。同意はコレクターごとに無効の状態で始まります。同意を撤回すると収集を止め、進行中の配送を中断し、設定されたアプリケーションの永続セッションを削除します。キューを使う場合は共有の同意状態を使って撤回を伝えます。直接送信ではホストがタブ間の通知を担当します。受信側で受付済みのリクエストは撤回後も残る場合があります。

## 配送

HTTP/JSON の送信ではブラウザが自動で付ける認証情報と Referer を外します。受信側ではアクセス方針を明示します。Bearer モードでは認証済みクレームを照合し、対象サービス、有効期限、テナント、アプリケーション、`liatris:write` 権限を確認してから本文を処理します。デモはループバックからの直接アクセスを許可します。

ローカルの参考実装は HTTP/JSON を受け付け、プロファイルのハッシュとペイロードを検証し、保存先の処理完了後に応答します。デモの保存先は、受け付けたレコードを SQLite に保存してから受領を返し、種別をターミナルに表示します。

サーバー側の転送アダプターは、SQLite の送信待ちテーブルから受領済みのイベントを読み出し、導入先が選んだストリーミング基盤へ送ります。各アダプターは UBI エンベロープを保ち、転送先の受理や失敗を送信待ちテーブルに反映します。Amazon Kinesis Data Streams は接続例です。gRPC の候補には、ブラウザからの unary gRPC-Web と受信側からのネイティブ gRPC への転送があります。キュー、再送、重複排除の契約は [イベントの永続配送](delivery.md) を参照してください。ページ離脱とオフライン復帰はそれぞれテストします。[gRPC-Web プロトコル](https://github.com/grpc/grpc/blob/master/doc/PROTOCOL-WEB.md)

検索分析では、結果の露出とクリックを別に記録します。順位付けの変更を測る場合は、表示した結果セットと順位付けの版を記録します。導入時の発火点の例は [イベント契約](event-contracts.md) を参照してください。
