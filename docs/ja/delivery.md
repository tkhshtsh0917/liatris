# イベントの永続配送

[English](../delivery.md)

## ブラウザと受信側

コレクターの `queue` に `createQueuedDelivery` のインスタンスを渡します。プロファイルとそのハッシュに加え、`sendBatch` に `createHttpBatchDelivery(endpoint)` で作った送信処理を指定します。収集の前にコレクターへ同意を渡します。`queued` は IndexedDB への保存完了、直接送信モードの `sent` は設定した配送処理の完了を示します。

キューの上限はオリジン・テナント・アプリケーションごとに512件です。最後の64件分は `result_impression`、`impression` 以外のレコード向けに予約され、送信可能なレコードの中でもこれらを優先します。上限に達すると新しいレコードを拒否します。配送対象は24時間で期限切れになり、キューの動作時に削除されます。一時的に失敗したレコードは同じ内容とイベント ID で再送し、`Retry-After` の待ち時間は上限付きで反映します。トークンはリクエストごとに取得し、キューには格納しません。同意、再接続、タブの表示状態の変化で再送を再開します。

同時に届くイベントは最大32件まで同じ IndexedDB トランザクションにまとめます。各イベントの `queued` は、そのトランザクションが確定した後に返します。

タブは IndexedDB 上の同意の世代、セッション、キューを共有します。同意を撤回すると、一つのトランザクションでセッションと送信待ちを削除し、世代を更新します。通知を受け取ったタブは進行中の送信を中止します。遅れて実行された処理が IndexedDB を更新する前にも世代を確認します。収集サービスにすでに達したリクエストは受理済みの場合があります。受理済みデータはサーバー側で削除します。

バッチは `application/vnd.liatris.batch+json` の JSON 配列で送ります。1リクエスト最大32件・128 KiB、各レコード最大32 KiB です。受信側は HTTP 200 と、送信された `event_id` ごとに1つの受領結果を返します。

| ステータス | キューの処理 |
| --- | --- |
| `accepted` | 受信側が保存を確認したため、削除します。 |
| `rejected` | 恒久的な失敗として、削除します。 |
| `retry` | 一時的な失敗として、再送のために保持します。 |

受領結果が欠けている、重複している、または解釈できない場合は、バッチ全体を再送します。リファレンス受信側はバッチの有効なイベントを一つの SQLite トランザクションで保存してから受領を返します。内容の競合はイベント単位で拒否します。ストレージ障害で保存が取り消された場合、そのトランザクションの対象はすべて再送します。同一テナント・アプリケーションで同じ内容を再送した場合は同じ1件として受理し、イベント ID が同じで内容が異なる場合は拒否します。単件用の `application/json` も引き続き利用でき、受理時は HTTP 204、同じ ID で内容が異なる場合は HTTP 409 を返します。データベースのパスは `LIATRIS_DB` で指定でき、デモの既定値は `liatris-demo.sqlite` です。本番データを保存する際は保存期間と削除の方針を決め、データベースファイルへのアクセスを制限します。

## ストリーミング先への転送契約

導入先が低遅延のストリーミング基盤を選び、サーバー側のアダプターで接続します。アダプターは送信待ちテーブルから確定済みのイベントを読み出し、UBI エンベロープと `event_id` を保ちます。転送先が受理を確認したイベントだけを転送済みにし、バッチの一部だけが失敗したときも、受理を確認できなかったイベントは再送できるように保持します。転送先ごとの上限とエラー処理はアダプターで扱います。ブラウザと受信 API の受領契約は配送先を問わず共通です。

転送先がイベントを受理してから送信待ちテーブルに反映するまでの間にプロセスが停止すると、再配送されることがあります。下流の読み取り側は収集範囲内の `event_id` で重複を排除できます。

## 接続例としての Amazon Kinesis Data Streams

一つの SQLite の送信待ちテーブルとストリームに対して、一つの転送ワーカーを動かします。`LIATRIS_KINESIS_STREAM`、`AWS_REGION` と、サーバー側の AWS 認証情報プロバイダーを設定します。ワーカーは `LIATRIS_DB` を使い、テナントとアプリケーションを選ぶ TOML プロファイルは `LIATRIS_PROFILE` で指定できます。ローカル検証で HTTP の Kinesis エンドポイントを指定した場合は HTTP/1.1 を使います。

```sh
npm run forward:kinesis
npm run test:kinesis
```

Compose のテストは、リファレンス HTTP 受信側へ単件とバッチで送信します。同じイベント ID を両方のリクエストで送り、Moto から読み戻した2件のエンベロープを照合します。バッチの一部だけが成功する場合は単体テストで検証します。IAM ロールは対象ストリームへの書き込みに限定し、本番の IAM ポリシーとサービスの制限は AWS 上で検証します。[Kinesis の IAM 文書](https://docs.aws.amazon.com/streams/latest/dev/controlling-access.html)

ブラウザ配送の検証は `mise run wasm` で WASM を作り、`npx playwright install chromium firefox webkit` でブラウザを入れて、`npm run test:browser` を実行します。受領応答の消失、再読み込みをまたぐ保持、別タブからの同意撤回、露出集中時の優先配送、部分的な受領、旧キューの移行に加え、オフラインからの復帰、429 に従う再送、保存容量エラーからの回復、タブの表示状態が戻ったときの配送再開を確認します。オフラインで新しいイベントを収集するには、そのページでセッション用 WASM を読み込み済みである必要があります。
