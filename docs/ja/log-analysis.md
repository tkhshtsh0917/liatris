# 検索行動ログの活用

[English](../log-analysis.md)

Liatris での収集同意は、導入先が計測開始を明示的に許可することです。許可されるまで収集を無効にし、同意の撤回時にはローカルでの収集を停止します。導入時に許可する送信先、項目、保存期間、利用目的を定義します。モデル学習への二次利用では、アクセス権、マスキング、削除も含めて別途レビューします。[セキュリティとプライバシー](security.md)

## クエリ単位の順位付けと検索

| 用途 | 必要なデータと最初の検証 |
| --- | --- |
| 検索の診断と評価 | クエリ、結果セット、表示順位、露出、クリック、確定成果を結合する。ゼロ件、クリックのない表示、観測が中断した表示をそれぞれ扱う。分母、観測率、順位付けの版を記録する。 |
| 偏りのあるフィードバックからの学習 | 表示リスト、候補・結果 ID、レイアウト、順位付けの版、実験群を保持する。ランダム化した場合は表示の割当確率も記録する。根拠のあるモデルや制御した順位の入れ替えで閲覧確率を推定する。IPS を関連性ラベルに基づく基準と比較し、観測のカバレッジ、重みの分散、標本数を確認する。表示順位だけで閲覧確率は特定できない。 |
| ベクトル検索モデルの学習 | アイテム単位で確定した成果を、定義した帰属期間内の露出やクリックからクエリへ結合する。その組を信頼度の高い正例とし、クリックのみの信号も保持する。難しい負例は妥当な候補から取り、既知の正例や曖昧な重複を除く。時期とセッションでデータを分割し、クエリ後のデータが特徴量に漏れないようにする。別に確保した関連性ラベルとオンライン実験で評価する。生の検索語には、承認済みの取得元と前処理が必要。 |

リクエスト単位の ID が、イベント間の結合キーになります。複数の検索やアイテム別の成果があるときの意味付けと帰属は、導入先が定義します。購入確率には関連性に加え、価格、在庫、露出も影響します。[Unbiased Learning-to-Rank](https://arxiv.org/abs/1608.04468) · [難しい負例を使ったベクトル検索の学習](https://arxiv.org/abs/2007.00808)

## 一連の検索行動の最適化

1. 短期間のクエリ、絞り込み、表示リスト、クリック、確定成果を時系列にする。セッションを境界にし、識別できる場合は目的の切り替わりで分ける。検索時は、その判断以前に得られた行動だけを使う。
2. 個別の行動履歴を使わない順位付けを基準にする。試すものには、反応がなかった項目の再提示を減らす、成果につながったカテゴリや絞り込みを上げる、クエリの言い換えを反映する、などがある。検索語の提案や、ゼロ件後に有用な条件を保ってやり直す機能も考えられる。
3. セッションまたは目的単位で観測期間を固定する。成功した割合、初回成功までの時間と操作数、ゼロ件からの回復を測る。クエリ単位の関連性、観測率、レイテンシー、利用者や検索の区分ごとの指標も確認する。結果が不明なセッションは不明として扱う。
4. 導入先の実験基盤で、サービスに合う単位でランダムに割り付ける。実際に適用した実験群を結果表示イベントに記録する。割当単位の中では施策を固定し、元の割当に基づいて評価する。ログから別のセッション施策を反実仮想評価する際は、施策のカバレッジと行動の割当確率を確認する。

まずセッション全体で評価し、そのうえでセッション中の文脈を使う施策を比較実験します。同じ一連の行動に探索や別の目的が含まれ、答えが見つかった時点で離脱することもあります。短い経路や検索回数の少なさは補助指標として扱います。[セッション単位の検索評価 sRBP](https://discovery.ucl.ac.uk/id/eprint/10081529/) · [セッションを使ったクエリ提案](https://research.google/pubs/learning-to-attend-copy-and-generate-for-session-based-query-suggestion/)
