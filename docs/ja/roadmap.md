クリックログに関する研究を踏まえ、M2 では画面に出した一覧と露出をクリックと独立して記録します。バイアスの統計的補正や順位付けモデルは、実験や分母のデータを使える後段で扱います。[Baidu のクリックログを使った実証研究](https://arxiv.org/abs/2404.02543) · [クエリ単位のクリック傾向推定の研究](https://arxiv.org/abs/2502.11414)

ブラウザで Beacon がキューに入ることと、受信側で永続化が完了することには、それぞれ異なる意味があります。M3 では障害時の受領確認と同意の扱いを検証します。M5 ではプライバシー保護集計の標準化動向に沿って、別の実験として扱います。[W3C Beacon](https://www.w3.org/TR/beacon/) · [IETF の DAP 仕様案](https://datatracker.ietf.org/doc/draft-ietf-ppm-dap/)

M2 には任意で有効にする時間指標と、離席・欠測を区別する受入試験を含めます。デモは結果の滞在時間と、その記録時のセッション経過時間を計測します。[指標定義](event-contracts.md#滞在時間と検索指標)

バイアスを考慮した順位付け、ベクトル検索モデル学習、セッション実験については[検索行動ログの活用](log-analysis.md)を参照してください。

## 追加の配送方式

接続先から要件が出た時点で gRPC を評価します。ブラウザからの受信には unary gRPC-Web、サーバー側の転送にはネイティブ gRPC を候補とします。HTTP と同じテストデータで、イベント項目、上限、イベント単位の受領、一時的・恒久的な失敗の区別を検証します。ブラウザから RPC を使う場合は、CORS、タイムアウト、キャンセルも確認します。

## セキュリティとプライバシーの公開条件

- **M2。** 既定では生の検索語を送らずに検索を計測する。新しい各項目の用途、データ分類、送信先、保存期間をレビューする。プロキシ、アプリケーション、デバッグ、バックアップも保存期間と削除の確認に含める。
- **M3。** タブ間の同意撤回と、識別子・送信待ちの削除を失敗時も含めて試験する。採集 ID を保って再送し、キューの保持時間とサイズに上限を掛ける。負荷の高い認証処理の前にリクエスト数と同時実行数を制限し、認証済みテナントにも割り当て上限を設ける。再送時に再度認可し、キューや保存先のログに認証情報が入らないことを確認する。
- **M4。** 信頼できる認証情報の発行元またはストアと統合し、スコープ限定の認証情報と鍵のローテーションを適用する。配備先の TLS と CORS を検証する。外部受付ではトークンの有効性とは別に、リプレイや悪用への対策を試験する。依存関係と処理系の更新確認に加え、実際に配布する SDK と WASM、および同梱する場合はスクリプトタグによる読み込みを検証する。

現在の対策と導入時の責務は、[セキュリティとプライバシー](security.md)を参照してください。
