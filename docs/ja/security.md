# セキュリティとプライバシー

[English](../security.md)

## ブラウザのデータと同意

HTTP 送信には `credentials: "omit"` と `referrerPolicy: "no-referrer"` を使い、リダイレクトは拒否します。相対パスはページのオリジンを基準に解決します。収集には HTTPS が必要です。ローカル開発では、同一オリジンのループバックで認証なしの送信を使えます。ブラウザは Origin を送ることがあり、基盤には IP アドレスなどの接続情報が見えます。[Fetch Standard](https://fetch.spec.whatwg.org/)

コレクターは収集が無効な状態で起動します。ホストが同意状態を渡し、その変更を他のタブにも伝えます。収集時に Liatris の Cookie やセッションをまたぐ訪問者 ID は発行しません。タブ内だけで追跡するにはメモリのセッションストアを使います。IndexedDB ストアは、用途を限定した不透明なセッション ID を同一オリジンのタブ間や再読み込み後で共有します。永続状態は明示的な同意撤回で削除し、有効期限後は次に対象となる活動があったときに ID を更新します。期限に達した時点で自動削除を予約する仕組みはありません。用途を限定したセッション ID と検索メタデータも、他の情報と結び付けられる場合があります。[W3C Privacy Principles](https://www.w3.org/TR/privacy-principles/)

承認された具体的な用途がある場合に検索語の収集を有効にします。検索語を必要としない計測には、不透明なクエリ ID や件数を含む宣言済みイベントを使います。フォームの値、アカウントや端末の ID、完全な URL、認証情報を独自項目に入れないようにします。ホスト側で検証している場合も、サーバー側でデータを検証し必要最小限にします。生イベント、セキュリティログ、集計結果の保存期間を別々に設定し、保存先、バックアップ、キューでの削除方法も確認します。デモは受け付けたレコードの種別だけを表示します。[OWASP Logging Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html)

## 収集リクエストの認証

導入サイト自身の収集エンドポイントを優先します。認証付き配送では、ホストが短命な書き込み専用 Bearer トークンを送信時に渡します。トークンはメモリに保持します。検証器には信頼する発行元または認証情報ストアを設定し、クレームを返す前にトークンを認証します。署名付きトークンには既存の JOSE ライブラリを使い、アルゴリズムと信頼する鍵を限定して、鍵のローテーションとクレーム検証を扱います。不透明なトークンは、信頼する認証情報ストアに照会できます。[RFC 6750](https://www.rfc-editor.org/rfc/rfc6750.html) · [RFC 8725](https://www.rfc-editor.org/rfc/rfc8725.html) · [RFC 9700](https://www.rfc-editor.org/rfc/rfc9700.html)

受信側は上限付きの本文を読み込み検証する前に、対象サービス、有効期限、`liatris:write`、テナント、アプリケーションを確認します。配送先の決定にはサーバー側のプロファイル、互換性の確認にはプロファイルのハッシュを使います。CORS と Origin チェックはブラウザからの接続を制限する仕組みで、トークン認証とは別に適用します。匿名でもトークンを発行できる場合は、発行口にも割り当て上限と悪用対策が必要です。購入完了などの機微なコンバージョンは、信頼できるサーバーイベントで裏付けます。[OWASP API Security Top 10](https://api-security.owasp.org/editions/2023/en/0x11-t10/)

外部エンドポイントを使う場合、CORS と `connect-src` には承認したオリジンだけを明示します。必要に応じてプリフライト応答で `Authorization` と `Content-Type` を許可します。長期の認証情報、署名鍵、下流の認証情報はサーバーに置きます。Kinesis への中継には対象ストリームへの書き込みに限定した IAM ロールを使い、ネイティブ gRPC への転送はサービスのワークロード ID で認証します。[Content Security Policy](https://www.w3.org/TR/CSP3/) · [Kinesis の IAM 文書](https://docs.aws.amazon.com/streams/latest/dev/controlling-access.html)

## 本番公開の条件

参考受信実装は最大 32 KiB の非圧縮 JSON を1件受け付けます。認証後の本文読み取りは既定で10秒以内です。デモのセキュリティヘッダーとソケットの制限はローカルページに適用します。外部公開前に、ヘッダーとリクエスト全体の時間制限、認証処理の同時実行上限と期限、認証前とテナント別の制限、再送・再生と重複に対する制御、永続化後の受領確認、ゲートウェイと保存先の監査ログのマスキングを整えます。

撤回時には進行中の通信が中止され、送信待ちが他のタブからも送られないことを確認します。再送に使う認証情報は元のテナント・アプリケーションに一致することを検証します。実際の保管設定で保存期間と削除を試験し、配布物のチェックサムと依存関係・処理系のセキュリティ更新も確認します。公開の条件は[ロードマップ](roadmap.md)で管理します。[NIST Secure Software Development Framework](https://csrc.nist.gov/pubs/sp/800/218/final)
